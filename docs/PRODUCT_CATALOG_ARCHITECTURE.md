# Product Catalog Architecture

## 목적

공동구매 물품 DB는 내부 운영자가 반복 사용하는 상품 조건의 기준점이고, 셀러 카탈로그는 우리 회사가 보유한 진행 가능 상품을 검색·확인하는 공개 범위가 제한된 조회 화면이다. 셀러 카탈로그는 쇼핑몰이 아니며 구매, 결제, 장바구니, 관심 표시, 즉시 공구 신청을 제공하지 않는다. 실제 영업과 공구 확정은 담당 매니저와 카카오톡 또는 전화로 진행한다.

## 데이터 관계

```text
Vendor 1 ─ N Brand 1 ─ N Product 1 ─ N ProductSku
                              │              │
Proposal N ───────────────────┴──────────────┘
Campaign N ───────────────────┴──────────────┘
```

- 공급처는 여러 브랜드와 공급·배송 기본 정책을 가질 수 있다.
- 브랜드는 여러 제품과 브랜드 공통 정책을 가질 수 있다.
- 제품은 셀러 설명, 공개 상태, 이미지와 제품 기본 정책을 가진다.
- SKU는 옵션, 가격, 재고 상태, 공개 여부와 제품 정책 예외를 가진다.
- SKU는 별도 메뉴가 아니라 제품 상세에서 관리한다.

## 기본값 상속과 override

정책은 `vendor → brand → product → sku` 순서로 해석한다. 하위 값이 없으면 상위 값을 사용하고 하위에 값이 있으면 override다. 화면에는 값과 `PolicySource`(`vendor`, `brand`, `product`, `sku`)를 함께 표시한다. 제품의 기존 평면 필드는 Campaign 호환을 위해 유지하며 제품 정책의 기준값으로 사용한다.

기본 판매 링크가 와이즈샵 또는 셀러 결제창을 가리킬 때 해당 링크가 사용 불가이면 저장을 차단한다. 와이즈샵과 셀러 결제창 가능 여부는 독립 값이다. 브랜드 PG 지원율은 회사가 지원받는 참고 조건이며 Campaign의 실제 셀러 추가 PG 지급률로 자동 복사하지 않는다.

## 내부 전용 정보

- 공급처와 공급처 연락처
- 공급가
- 총·셀러 기본·회사 수수료율
- 브랜드 PG 지원 여부와 지원율
- 정산 메모, 발주 담당자, 내부 메모
- 판매 링크 정책 세부정보
- 내부 제안서 원본과 활동 로그

내부 전용 데이터는 `ProductMaster`에 존재할 수 있으나 셀러 서비스 응답에 포함하지 않는다.

## 셀러 공개 정보

`SellerCatalogProduct`는 셀러 전용 DTO다. 브랜드, 제품명, 이미지, 카테고리, 셀러용 설명, 예상 정상가·공구가 범위, 배송 안내, 샘플 가능 여부, 공구 가능 상태, 공개 Badge, 공개 옵션, 담당 매니저만 포함한다. 내부 모델을 컴포넌트에 넘긴 뒤 숨기는 방식이 아니라 service layer에서 공개 DTO로 변환한다.

## 셀러 공개 상태

`sellerPortalVisible=false`이면 카탈로그 목록과 상세 조회 모두 `null` 처리한다. 공개 상품은 `available`, `coming_soon`, `paused`, `sold_out`, `closed` 상태를 문구와 Badge로 표시한다. 내부 공동구매 물품 DB는 공개 여부와 관계없이 모두 조회한다.

## 담당 매니저 중심 운영

카탈로그 상단과 상품 상세에 담당 매니저를 표시한다. 담당자가 없으면 기본 담당자 김병희 또는 향후 회사 대표 문의 채널을 사용한다. 상세의 유일한 주요 행동은 “담당 매니저에게 문의”이며 현재는 Mock 안내를 제공한다.

## 제안서와 카탈로그

제안서는 브랜드 협의 자료, 스프레드시트, 미리보기 이미지와 여러 Product/SKU 관계를 가진 내부 영업 자산이다. 카탈로그는 공개 허용된 상품의 셀러 안전 정보만 검색하는 화면이다. 제안서 원본을 셀러에게 전체 공개하지 않으며 매니저가 기존 방식대로 필요한 이미지 또는 링크만 전달한다.

## Campaign snapshot 원칙

Campaign은 Product 또는 SKU를 선택할 수 있다. 선택 시 브랜드, 공급처, 가격, 배송비, 수수료, 기본·사용 가능 링크, 브랜드 PG 지원, 샘플, 발주 마감과 배송 정책을 불러온다. 저장 시 `productMasterId`, `skuId`, `productMasterVersion`, `capturedAt`, 해석된 값과 정책 출처를 snapshot으로 보존한다. 마스터가 변경돼도 기존 Campaign의 정산 조건은 변경하지 않는다. 기존 Settlement 계산식은 변경하지 않는다.

## 검색과 보안

검색 대상은 브랜드명, 제품명, 공개 SKU 옵션명, 카테고리와 셀러용 설명이다. 셀러 경로는 `/seller/catalog`, 상세는 `/seller/catalog/:productId`다.

보안은 두 단계다.

1. Route Guard가 seller portal 세션의 `/master/products/:id` 직접 접근을 셀러 카탈로그로 돌린다.
2. 데이터 접근 계층의 `listSellerCatalog`와 `getSellerCatalogProduct`는 공개·활성 조건을 검사하고 셀러 전용 DTO만 반환한다.

실제 Supabase Auth 연결 시 동일 규칙을 RLS로 강제해야 한다. `product_masters` 내부 조회는 직원 역할만 허용하고 셀러용 view/RPC는 공개 컬럼만 반환해야 한다.
