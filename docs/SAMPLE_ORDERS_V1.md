# 샘플관리 1차 (운영 193 기반, 배포 전 검증 대기)

## 범위

- 기존 샘플관리 메뉴에 신규 요청·승인·발주파일·배송 상태 흐름을 추가한다.
- 기존 샘플 기록은 기존 화면에 유지한다. 자동 이관·삭제·정산 재계산은 하지 않는다.
- 상품 조회/정규화 및 빠른 SKU 등록은 기존 productService와 QuickSkuRegistrationModal을 사용한다.
- 요청자는 로그인한 승인된 회사 계정으로 기록한다. 승인 처리는 기존 회사 사용자 접근정책을 따른다.
- 상품/SKU ID는 참조만 한다. 비용과 수령정보는 샘플 요청에 복사하여 이후 상품 조건 변경과 분리한다.
- 셀러 metadata의 recipientName, shippingPhone, shippingAddress를 읽는다. 없는 값은 직접 입력하며 샘플에서 셀러 DB를 수정하지 않는다.

## 저장 및 동시성

- 새 프로젝트·테이블·migration 없음.
- 기존 workspace_state에 storage_key=t3_sample_order_book_v1, payload={schemaVersion:1,orders:[]}로 저장한다.
- 일반 localStorage 동기화 키에 추가하지 않는다. 이 키의 모든 쓰기는 서버 revision을 조건으로 하는 compare-and-swap이다.
- 최초 insert 충돌, 수정 revision 충돌 시 실패로 반환한다. 자동 덮어쓰기·재발주하지 않는다.
- 기존 workspace_state_history 트리거가 변경 전 payload를 보존한다. 샘플 자체에도 요청자·처리자·상태 이력을 저장한다.
- SAMPLE-YYYYMM-UUID 식별자는 월별 다중 사용자 등록 시에도 중복되지 않는다.
- 승인된 발주대기 샘플만 파일 생성 가능하다. 선택한 전체 샘플의 exportBatchId를 한 번의 원자적 갱신으로 기록한 후 다운로드한다.
- 다운로드 실패 시 동일 배치를 재다운로드한다. 새 배치로 재발주하지 않는다. 취소 샘플 포함 배치는 다운로드를 차단한다.
- 실제 발주 여부는 별도 기록한다. 파일 생성만으로 발주완료나 정산반영 처리하지 않는다.
- 정산반영은 이번 버전에서 false로만 생성한다. 비용 연결·차감 계산·과거 Snapshot 수정 없음.

## 발주모아

확인된 업로드 규격이 없어 내부 Excel(.xlsx)만 제공한다. 실제 발주모아에 바로 업로드 가능한 양식이라고 표시하지 않는다.
필요한 자료: 현재 사용하는 발주모아 주문등록 업로드 양식(헤더가 있는 빈 Excel 또는 개인정보를 제거한 예시).
내부 파일: 주문/샘플 식별번호, 상품, 옵션, 수량, 수령인, 연락처, 주소, 배송메모.
연락처와 수식처럼 보이는 텍스트도 Excel 문자열로 보존한다. 발주모아·공급사 전송 또는 주문 실행은 하지 않는다.

## 검증

- scripts/runSampleOrders.mjs: 격리 fixture 기반 13개 검사. SKU ID/다른 브랜드/선택 콜백/금액/지원액/필수값/상태 이력/중복 및 동시 Export/셀러 기본값/Excel 왕복 테스트.
- test:product-import-safety 통과.
- test:settlement-document 15/15 통과.
- test:settlement-payout: 정산 더미데이터 부재로 실행 실패. 이를 통과로 간주하지 않는다.
- 실제 DB 테스트와 브라우저 UI 테스트는 미실행. 검증용 브라우저가 내부 미리보기 접근을 ERR_BLOCKED_BY_CLIENT로 차단했다. 다른 네트워크 경로로 우회하지 않는다.
- 실제 SKU·셀러로 등록/빠른 등록/승인/파일 생성/새로고침 후 복원/동시 발주 테스트를 완료하기 전 운영 배포하지 않는다.
- 운영 데이터에 테스트용 상품·SKU·샘플을 생성하지 않았다.
