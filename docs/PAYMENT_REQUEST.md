# 지급·입금 요청

## 목적

확정된 셀러 정산을 실제 송금 전 운영 흐름으로 연결한다. MVP는 localStorage 상태 관리와 수동 완료 체크만 제공하며 실제 자금 이동은 하지 않는다.

## 요청 방향

- `company_to_seller`: 공급사 링크 또는 와이즈샵 링크의 회사 → 셀러 지급
- `seller_to_company`: 셀러 결제창의 셀러 → 회사 입금

정산서, 요청, Campaign은 각각 `settlementId`, `campaignId`, `sellerId`로 연결한다.

셀러와 매니저 지급요청은 `recipientType`, `recipientId`, `recipientName`, `sourceVersion`으로 분리한다. 동일 Campaign에서도 두 요청의 증빙과 상태는 독립적이다. 매니저 일괄 요청은 `batchRequestId`로 묶으며 상세 규칙은 `MANAGER_PAYMENT_REQUEST.md`를 따른다.

## 승인과 완료 흐름

회사 → 셀러는 증빙 확인 후 `approval_pending`으로 요청하고, 대표 승인 후 `approved`, 담당자의 지급 완료 수동 체크 후 `payment_completed`가 된다.

셀러 → 회사는 증빙 확인 후 `request_ready`, 셀러 전달 후 `sent`, 실제 입금 확인 후 `remittance_confirmed`가 된다. 입금 요청액은 증빙 요청 금액과 별도 필드로 저장한다.

## 상태

| 상태 | 의미 |
| --- | --- |
| `draft` | 요청 초안 |
| `evidence_pending` | 증빙 최종 확인 대기 |
| `request_ready` | 지급·입금 요청 생성 가능 |
| `approval_pending` | 대표 승인 대기 |
| `approved` | 승인 완료, 지급 예정 |
| `sent` | 셀러에게 입금 요청 전달 |
| `payment_completed` | 회사 → 셀러 지급 수동 확인 완료 |
| `remittance_confirmed` | 셀러 → 회사 입금 확인 완료 |
| `on_hold` | 사유가 있는 보류 |
| `rejected` | 반려 |

## 실제 은행 이체 연동 시 교체할 부분

`paymentRequestService`의 승인 이후 실행 부분을 은행 지급 어댑터로 교체한다. 요청 데이터와 UI 계약은 유지하고, 멱등성 키, 계좌 검증, 승인 권한, 웹훅 서명, 실패·재시도, 거래 원장과 일일 대사를 추가한다. 홈택스·증빙 API는 지급 실행과 분리된 어댑터로 연결한다.

## 지급요청 중심 UX

지급 관리 탭은 `지급 요청 → 대표 승인 → 지급 예정 → 지급 완료 → 증빙 검수 → 원천세 리스트` 순서다. 기본 진입은 지급 요청이며 목록 행을 선택하면 Drawer가 아닌 넓은 지급요청 상세 화면을 연다.

상세는 지급 대상 요약, 정산금 계산, 증빙자료, 계좌 확인, 원천세, 지급요청 상태, 승인·지급 이력 순서다. 상단 단계 표시는 `정산 확정 → 증빙 업로드 → 증빙 승인 → 지급 요청 → 대표 승인 → 지급 완료` 흐름과 현재 행동을 문구로 안내한다.

## 증빙 업로드와 관리자 검수

증빙자료 선택·교체는 지급요청 상세에서만 제공한다. localStorage에는 기존과 같이 파일 메타데이터만 저장한다. 증빙 검수 탭은 허수정 담당자가 업로드된 셀러·매니저 자료를 필터링하고 승인 또는 사유 필수 반려만 수행하는 관리자 검수 전용 화면이다. 이 탭에서는 업로드, 지급요청 생성, 지급 완료 처리를 제공하지 않는다.

## 상태별 버튼

- 증빙 없음: `증빙자료 업로드`
- 업로드 완료: `증빙 검수 요청`, 보조 `파일 교체`
- 검수 중: 버튼 없이 `허수정 검수 대기 중`
- 반려: `증빙 다시 업로드`와 반려 사유
- 증빙 승인: `지급요청 생성`
- 대표 승인 대기: 버튼 없이 대기 안내
- 대표 승인 완료: `지급 완료 처리`
- 지급 완료: 버튼 없이 완료일과 처리자

서로 다른 단계의 Primary 버튼을 한 상세 화면에 동시에 노출하지 않는다.

## 지급요청 생성 차단

정산서 확정, 증빙 유형 확정, 필수 증빙 업로드와 승인, 계좌 확인, 계산 오류 없음이 필요하다. 프리랜서는 원천세 리스트 등록도 완료해야 한다. 부족한 조건은 비활성 버튼 아래에 이유를 표시한다.

## 셀러와 매니저 분리

Campaign과 Settlement의 셀러·매니저 지급 카드는 각자의 증빙, 원천세, 지급요청 상태와 상세 이동을 독립적으로 표시한다. 어느 한쪽의 증빙 승인이나 지급 완료를 다른 쪽에 공유하지 않는다.
