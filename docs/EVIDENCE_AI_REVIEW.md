# 증빙 AI 1차 판독 MVP

## AI와 사람의 역할

AI는 증빙 유형과 금액·날짜·상호를 1차 추출하고 정산 기준금액과의 일치 여부를 추천한다. AI는 최종 승인자가 아니다. 허수정 정산 담당자가 원본 미리보기, AI 결과, 계좌와 정산 상태를 확인하고 반드시 승인 또는 반려한다.

## 사업자 유형별 비교 기준

| 대상 | 비교 기준 | 기대 금액 |
| --- | --- | ---: |
| 법인·일반사업자 | `tax_invoice_total` | 부가세 포함 최종 정산 기준금액 |
| 간이사업자 | `cash_receipt_amount` | 부가세 제외 지급 기준금액 |
| 프리랜서 | `manual_review` | 원천세 리스트 계산 검증 |

원 단위 정수로 비교하며 `EVIDENCE_AMOUNT_TOLERANCE = 0`이다. 추출 금액과 기대 금액이 같으면 일치, 다르면 불일치다. 금액 미추출 또는 낮은 신뢰도는 직접 확인 필요로 표시한다.

## 셀러 결제창 예외

셀러 결제창의 증빙 발행금액과 회사 입금 요청액은 의미가 다를 수 있다. 두 값을 같은 금액으로 자동 판정하지 않고 `manual_review`와 `needs_review`를 사용한다.

## Mock 분석

`MockEvidenceAiProvider`는 테스트 가능한 파일명 규칙을 사용한다.

- `matched`: 기대 금액 반환
- `mismatch`: 기대 금액과 다른 금액 반환
- `unclear`: 낮은 신뢰도와 금액 미추출
- `failed`: 분석 실패
- 기타: 전달된 mock 금액이 없으면 직접 확인 필요

결과는 `t3_company_os_evidence_ai_reviews`에 증빙 ID별로 저장한다. 셀러와 매니저는 evidence ID가 다르므로 결과와 예외 승인 사유를 공유하지 않는다.

## 오판과 예외 승인

AI 일치만으로 증빙이 승인되지 않는다. 불일치 상태에서는 승인 버튼을 차단하고 허수정이 불일치를 확인한 뒤 예외 승인 사유를 필수 입력해야 한다. 확인 필요 또는 분석 실패는 원본을 직접 확인하고 검수 메모와 함께 처리한다. 불일치는 기존 My Work를 high 우선순위로 바꾸고 경고 이력을 추가하며 새 Work Item을 만들지 않는다.

## 실제 Vision API 연결 구조와 보안

예정 구조는 `React → 서버/Supabase Edge Function → Vision API → 구조화된 추출 결과 → 금액 비교 → 허수정 최종 승인`이다. 브라우저 코드나 localStorage에 API 키를 저장하지 않는다. 실제 provider는 `EvidenceAiProvider`를 구현하고 private storage의 단기 서명 URL 또는 서버 내부 파일 참조만 사용한다.

## 감사 이력

AI 결과에는 분석 시간, 분석 주체, 모델 버전, 추출값, 신뢰도, 경고와 비교 사유를 저장한다. 사람 검수에는 검수 상태, 검수자, 시간, 메모, 반려 사유와 예외 승인 사유를 별도로 저장한다. 원본 revision은 덮어쓰지 않는다.
