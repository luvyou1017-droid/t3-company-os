# T3 Company OS UX Bible

## 1. UX 목표

T3 Company OS는 정보를 많이 보여주는 시스템이 아니라,
직원이 지금 해야 할 일을 빠르게 이해하고 처리하게 만드는 시스템이다.

모든 화면은 다음 질문에 답해야 한다.

- 지금 무엇을 해야 하는가?
- 왜 해야 하는가?
- 언제까지 해야 하는가?
- 어디에서 처리하는가?
- 완료하면 다음 단계는 무엇인가?

## 2. Work First

직원은 메뉴를 탐색하기 전에 My Work에서 오늘 업무를 확인한다.

Home과 My Work는 역할별로 다르게 보여야 한다.

대표:
- 승인 대기
- 지급 예정
- 정산 지연
- 전체 운영 위험

정산·CS 담당자:
- 신규 CS
- 판매 데이터 확인
- 정산서 작성
- 증빙 확인
- 지급 준비

MD:
- 브랜드 링크 요청
- 브랜드 답변 대기
- 제안서 작성
- 판매 데이터 요청

매니저:
- 본인 공동구매
- 링크 검수
- 매출 전달
- 최저가 확인
- CS 확인
- 정산 검토

## 3. 화면 유형 원칙

정보가 적고 빠른 확인만 필요한 기능:
- 작은 modal 또는 drawer 사용 가능

정보가 많고 여러 단계의 작업이 필요한 기능:
- 전용 상세 페이지 사용

다음 화면은 전용 상세 페이지를 기본으로 한다.

- 공동구매 상세
- 판매 데이터 상세
- 정산 상세
- 지급 상세
- 셀러 상세
- 브랜드 상세

Drawer는 다음 용도로만 사용한다.

- 간단 미리보기
- 빠른 상태 변경
- 짧은 메모 입력
- 5개 이하 필드 수정

정산처럼 정보가 많은 화면을 좁은 Drawer에 넣지 않는다.

## 4. 목록과 상세

모든 주요 기능은 다음 흐름을 따른다.

목록
→ 검색·필터
→ 항목 선택
→ 전용 상세 페이지
→ 처리
→ 목록으로 돌아가기

목록으로 돌아왔을 때 다음 상태를 유지한다.

- 검색어
- 필터
- 정렬
- 페이지
- 스크롤 위치

## 5. 상세 페이지 구조

상세 페이지는 다음 순서로 구성한다.

1. 제목과 현재 상태
2. 핵심 요약
3. 오늘 해야 할 일
4. 세부 탭
5. 처리 버튼
6. 활동 이력

정보량이 많은 경우 탭을 사용한다.

예시:

공동구매 상세:
- 개요
- 타임라인
- 체크리스트
- 링크·발주
- 제안서
- 샘플
- CS
- 판매 데이터
- 정산
- 파일
- 이력

정산 상세:
- 요약
- 계산 과정
- 차감 내역
- 세무·증빙
- 검토·승인
- 정산서
- 이력

## 6. 행동 버튼 원칙

한 화면에서 Primary 버튼은 원칙적으로 하나만 강조한다.

예:

- 일정 등록
- 판매 데이터 확정
- 매니저 검토 완료
- 대표 승인
- 지급 준비

나머지는 secondary, outline 또는 추가 작업 메뉴로 배치한다.

현재 상태에서 실행할 수 없는 버튼은 비활성화하고,
비활성화 이유를 설명한다.

예:

“증빙 확인 후 지급 준비가 가능합니다.”

## 7. 상태 원칙

상태는 색상만으로 표현하지 않는다.

항상 다음을 함께 사용한다.

- 상태 문구
- 배지
- 필요 시 아이콘
- 다음 행동 안내

예:

빨강:
긴급, 오류, 지연

주황:
검토 필요, 오늘 마감

파랑:
진행 중

보라:
정산·승인

초록:
완료

회색:
대기, 미정, 취소

## 8. 테이블 원칙

테이블에는 실제로 비교에 필요한 정보만 표시한다.

상세 정보는 상세 페이지에서 보여준다.

테이블 규칙:

- 금액은 우측 정렬
- 이름과 제목은 좌측 정렬
- 상태는 배지 사용
- 날짜 형식 통일
- 긴 텍스트는 말줄임
- 행 전체 클릭 가능
- 모바일에서는 카드형으로 전환

가로 스크롤은 가능한 한 피한다.

필요한 경우 중요하지 않은 열을 숨기거나
컬럼 설정 기능을 제공한다.

## 9. 폼 원칙

입력 폼은 업무 순서대로 섹션을 나눈다.

예:

- 기본 정보
- 담당자
- 일정
- 링크
- 수수료
- 정산
- 메모

필수값은 최소화한다.

오류는 화면 상단이 아니라 해당 입력란 바로 아래에 표시한다.

입력 중 닫을 경우 작성 내용이 있다면 경고한다.

## 10. 빈 상태

데이터가 없을 때 단순히 빈 화면을 보여주지 않는다.

다음을 함께 보여준다.

- 데이터가 없는 이유
- 다음에 해야 할 행동
- 바로 실행할 버튼

예:

“아직 판매 데이터가 없습니다.
파일을 업로드하거나 수기로 입력해주세요.”

## 11. 오류와 경고

오류는 무엇이 잘못됐는지만 말하지 않고,
어떻게 해결하는지도 안내한다.

나쁜 예:
“오류가 발생했습니다.”

좋은 예:
“총수수료율은 셀러 수수료율보다 높아야 합니다.”

중요 오류는 승인·확정·지급을 차단한다.

## 12. 정보 공개 범위

내부용 정보와 외부 전달용 정보를 명확히 분리한다.

셀러 전달용 화면에는 다음 정보를 노출하지 않는다.

- 벤더 수수료
- 회사 귀속액
- 매니저 지급액
- 내부 승인 이력
- 내부 메모
- 다른 셀러 정보

외부 전달용 문서는 별도 컴포넌트와 별도 데이터 변환 함수를 사용한다.

## 13. 모바일 원칙

모바일에서는 다음을 우선한다.

- 오늘 업무
- 상태 확인
- 간단 승인
- CS 확인
- 알림

복잡한 정산 계산과 대형 테이블은
데스크톱 사용을 기본으로 한다.

모바일에서는 카드형 요약과 핵심 버튼만 제공한다.

## 14. 접근성

- 색상만으로 의미 전달 금지
- 충분한 텍스트 대비
- 키보드로 주요 기능 접근 가능
- 버튼 이름은 동작을 명확히 표현
- 클릭 영역은 충분히 크게 유지
- 긴 업무 화면에서도 글자가 지나치게 작아지지 않게 한다

## 15. UX 검증 질문

새 화면을 만들기 전에 반드시 확인한다.

- 이 화면의 사용자는 누구인가?
- 사용자가 여기서 결정해야 할 것은 무엇인가?
- 가장 중요한 정보는 무엇인가?
- 다음 행동은 무엇인가?
- 다른 화면에서 이미 입력한 정보를 다시 요구하고 있지 않은가?
- 정보가 많다면 전용 상세 페이지가 필요한가?
- 외부에 노출되면 안 되는 정보가 있는가?

## 16. 핵심 원칙

T3 Company OS는
기능이 많은 시스템보다
업무가 명확한 시스템을 지향한다.

직원이 화면을 보고 생각하게 하지 않는다.

시스템이 다음 행동을 명확히 알려준다.
